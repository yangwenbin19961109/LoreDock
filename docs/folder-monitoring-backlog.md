# 文件夹增量监听功能规划

> 产品排期：第二期功能，不属于当前一期 Phase 0～7 的开发和发布范围。本期只保留已经验收通过的一次性文件夹递归导入。

## 目标

允许用户把一个本地文件夹与知识库建立可撤销的长期关联。LoreDock 在获得明确授权后检测新增、修改、移动、重命名和缺失文件，并只重建受影响的资料与索引。

## 二期范围

- 在 Tauri 桌面层选择并授权目录，不通过普通 HTTP 请求接受任意本地绝对路径。
- 保存可撤销的目录关联，并在程序重启后安全恢复。
- 首次扫描建立路径、内容哈希、大小和修改时间基线。
- 对连续文件系统事件进行防抖，避免保存一次触发多次索引。
- 新增或内容变化时执行增量导入；移动和重命名尽量保持稳定来源身份。
- 目录或外接磁盘暂时离线时标记状态，不自动删除资料。
- 删除确认需要宽限期或用户确认，并一致清理原始副本、解析产物、索引、向量和缓存。
- 提供暂停监听、立即扫描、解除关联、错误诊断和逐文件状态。

## 产品与安全边界

- 只访问用户明确选择并授权的目录，规范化路径并拒绝越界。
- 符号链接默认不跟随；如未来开放，需要单独授权和循环检测。
- 不监控整个磁盘、用户主目录或未选择的相邻目录。
- 不把临时离线等同于用户删除，不静默丢失知识库资料。
- 后台监听失败不能影响现有资料搜索、BM25 降级或 MCP 读取。
- 服务器/Web 版本需要使用独立的服务器目录挂载方案，不能复用桌面本地路径授权。

## 推荐实施顺序

1. 调研 Windows、macOS、Linux 的目录授权、文件事件和应用重启恢复差异，记录 ADR。
2. 定义目录关联、文件快照、变化事件和来源绑定的数据模型及迁移。
3. 实现手动“立即扫描”和差异预览，不先启用后台自动处理。
4. 实现新增与修改的原子替换、内容哈希去重和失败恢复。
5. 实现移动/重命名识别、缺失宽限期和显式删除确认。
6. 接入后台监听、防抖、暂停/恢复、诊断和跨平台测试。

## 验收条件

- 重启 LoreDock 后，用户授权仍有效或能给出明确的重新授权提示。
- 只有新增或变化的文件被重新处理，未变化资料保持稳定来源 ID。
- 文件连续保存不会产生重复资料或并发重建同一来源。
- 文件夹暂时离线不会删除知识库资料。
- 移动、重命名、删除和恢复场景有确定且可测试的处理规则。
- 解除关联后停止访问目录，但不会在未确认时删除已经导入的知识库资料。
- Windows、macOS、Linux 均完成真实文件系统事件与权限恢复测试。

## 排期位置

该功能归入第二期，不作为一期验收或发布条件。本期不新增持久目录权限、监听进程、变化事件表、自动重建或后台扫描。
