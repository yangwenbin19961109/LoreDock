# Phase 5 交付记录

## 第一批：HTML 文件导入

本批扩展现有本地文件摄取管线，新增 `.html` 与 `.htm`：

- Core 保存原始 HTML 可信副本，解析产物和索引仍可重建。
- 使用 Python 标准库进行确定性文本提取，不增加运行依赖或安装包体积。
- 保留块级内容换行和 HTML 实体解码；优先使用文档 `<title>`，缺失时回退到文件名。
- 排除 `script`、`style`、`template`、`noscript`、`iframe` 和 `object` 内容，不执行脚本、不加载外部资源。
- 沿用 100 MiB 单文件上限、路径边界、内容哈希去重、任务状态、Child/Parent 分块和 BM25-only 降级。
- 桌面文件选择器、拖放提示和首次使用说明同步展示 HTML 支持。

本批不包含 URL 抓取、CSS 可见性计算、浏览器渲染快照、图片 OCR、附件下载或 HTML 原始版面还原。来源预览继续显示由 Core 安全提取的结构化文本。

## 验收范围

1. `.html` 与 `.htm` 可以通过 Core 和桌面入口导入、索引、搜索及引用读取。
2. 标题、段落、列表和实体文本可读，主动内容与嵌入内容不进入解析文本。
3. HTML 原件不被修改；删除和索引重建继续使用现有一致性路径。
4. 原有 Markdown、TXT、PDF 和 DOCX 解析回归保持通过。

## 第二批：PPTX/XLSX 技术准入

已完成解析依赖、许可、打包面和定位模型评估，并接受 [ADR 0015：受限的只读 OOXML 资料解析](decisions/0015-ooxml-readonly-ingestion.md)：两种格式共用安全的 ZIP/关系/XML 基础层，不引入 LibreOffice，不采用完整 Office 编辑对象模型。PPTX 以幻灯片作为页面和默认 Parent，XLSX 以工作表及连续行区块作为 Parent，并保留单元格坐标。下一步先实现和攻击性测试 OOXML 容器边界，再分别接入 PPTX、XLSX 文本解析。

安全 OOXML 基础层已经实现：不落盘解压，限制成员数、单部件/总解压大小和压缩比，拒绝路径穿越、重复部件、加密部件、不支持的压缩方法、DTD/实体及越界内部关系；外部关系只作为元数据返回，不发起网络访问。lxml 由间接依赖提升为显式依赖，版本仍使用锁文件中已有的 6.x，不新增第二套 XML 运行时。

PPTX 已接入公开导入链路：按 `presentation.xml` 关系顺序读取幻灯片，提取文本框与表格文本，将每张幻灯片记录为可引用页面，并标记隐藏幻灯片。原始文件仍是事实来源，解析结果与索引可重建。当前不提取演讲者备注、图表数值、SmartArt、图片 OCR、动画或外部链接内容，也不承诺还原演示版面。

PPTX 自动回归覆盖关系定义的演示顺序、文本框、表格转义、隐藏幻灯片、页码范围、服务层导入、BM25 检索和引用读取。当前 Core 全量结果为 110 项通过、1 项系统测试默认跳过；Ruff 与 Pyright 通过。Web 格式、lint、类型检查和 38 项单元测试通过，文件选择器 PPTX 契约的 2 项浏览器测试通过。桌面开发程序运行期间 Rust 构建目录被占用，因此本批未重建桌面二进制或安装包。

2026-09-07，PPTX 桌面人工验收通过。验收期间发现并修复“Core 已连接但启动数据只尝试加载一次”的 D-A04，确认是前端瞬时失败恢复缺陷而非知识数据丢失。

XLSX 已接入公开导入链路：按工作簿关系顺序读取工作表，支持 shared strings、富文本 shared strings、inline strings、字符串、布尔值、错误、数值、公式缓存值，以及无缓存值时的公式文本。输出保留工作表名称、可见/隐藏状态和显式单元格坐标，工作表映射为引用页码。公式永不执行；首版不展开空白区域，不解析图表、数据透视表、宏或外部链接，也不承诺复杂日期和数字格式的显示还原。

XLSX 自动回归覆盖解析器、服务层与 HTTP 上传契约，包括工作表关系顺序、字符串类型、数值、布尔值、公式、隐藏状态、坐标、BM25 检索和引用页码。Core 全量验证为 113 项通过、1 项系统测试默认跳过；Web 格式、lint、类型检查、38 项单元测试、生产构建和 2 项浏览器文件选择契约通过。

安全 OOXML 基础层的定向测试覆盖正常 XML/关系、外部关系、路径穿越、重复部件、成员数、单部件/总解压量、压缩比、非支持压缩方法、损坏 ZIP、DTD/实体和越界关系。全量测试保留既有 Starlette/httpx 弃用警告。
