## 关于搜索排序与分数

当前搜索结果已有后端 `score` 字段，并按最终检索排序返回，UI 已展示“相关度”。混合检索的最终分数来自词法召回、向量召回和排名融合，不能直接解释为“相似概率”，也不能仅凭某一条结果排第三就判断向量模型质量差。

整改时 UI 使用“相关度”而不是“准确率”或“概率”。如果需要展示百分比，只能作为当前结果集内的相对归一化显示，并明确其含义；诊断和评测仍保留原始融合排名、各召回通道排名及模型信息。任何模型、分块、权重或阈值调整都必须先增加固定回归查询，再依据指标决定。

## 修复排期

### 整改批次 A：恢复完整验收路径

1. P3-A01：修复拖放事件、投放区域和错误反馈，并增加前端交互测试。
2. P3-A02：建立搜索结果到资料预览锚点的稳定定位与高亮。
3. P3-A05：增加搜索重置按钮和完整状态清理。

完成标准：用户可通过拖放导入资料，搜索后可定位命中，并能一键回到未搜索状态。

### 整改批次 B：桌面布局与窗口约束

1. P3-A03：重构预览标题栏，隔离文件名和危险操作区。
2. P3-A06：明确 Tauri 默认窗口尺寸、最大化能力和缩放策略；调整页面高度与内部滚动容器。
3. 对默认窗口、最大化、100% 和 125% 缩放执行视觉回归。

完成标准：两种窗口状态下无控件重叠、主页面无纵向滚动条，内容区域各自正确滚动。

### 整改批次 C：检索可解释性基线与后置质量回归

1. P3-A04：在搜索列表显示“相关度”和检索模式，不把余弦或融合分数描述为概率。
2. 保留逐题查询、返回来源和分数等离线诊断信息，同时保持现有客户端契约兼容。
3. 首轮固定评测已完成 BM25、向量和混合检索对照，作为后续调优基线。
4. Phase 4 完成 Agent/MCP 真实接入并积累代表性查询后，再扩充评测集并评估融合权重、分块、模型或轻量 reranker。

Phase 3 完成标准：排序依据在 UI 中可理解，现有检索顺序稳定，首轮诊断可复现。算法质量调优单独后置，不阻塞本阶段。
