# ADR 0015: 受限的只读 OOXML 资料解析

- 状态：Accepted
- 日期：2026-09-07
- 决策负责人：LoreDock 项目负责人
- 替代：无

## 背景

Phase 5 第二批需要支持 `.pptx` 与 `.xlsx`，同时保持桌面安装轻量、解析结果可重建、引用稳定，并把用户提供的 Office 文件视为不可信输入。两种格式都属于 ECMA-376 Office Open XML 容器：文件是 ZIP 包，演示文稿和工作簿由多个 XML 部件及关系组成。

成熟库并不完全符合 LoreDock 的只读需求：`python-pptx` 提供完整的创建、修改和往返能力，但强制依赖 Pillow、XlsxWriter 与 lxml；`openpyxl` 的只读模式适合大表格，但官方明确提示默认 XML 解析不防御 quadratic blowup 与 billion laughs，需要额外安全措施。LoreDock 只需要提取可搜索文本、基本结构和稳定定位，不需要写回 Office 文件。

## 决策

实现一个 LoreDock 自有、范围受限的只读 OOXML 适配层，供 PPTX 与 XLSX 解析器复用：

1. 使用标准库 `zipfile` 读取成员，不把归档解压到文件系统。
2. 在打开 XML 前验证成员数量、单成员解压大小、总解压大小、压缩比、加密标记和规范化成员名；拒绝路径穿越、重复关键部件和超限归档。
3. 使用安全配置的 lxml 解析需要的 XML 部件，禁用实体解析、DTD、网络访问和超大树。lxml 已由现有 `python-docx` 运行链路带入，但将改为 LoreDock 的显式直接依赖并记录 BSD 许可；这不会新增一套解析运行时。
4. 不实现通用 OOXML 对象模型，也不修改或写回源文件。仅支持明确列出的部件、命名空间与关系类型，未知扩展跳过并记录有界诊断。
5. PPTX 按演示文稿关系确定幻灯片顺序，按形状 XML 顺序提取标题、正文和表格；每张幻灯片形成页面范围，引用保留 `page_start/page_end`。首版不做图片 OCR、图表数据、SmartArt 重建、动画、母版占位文字或原始版面还原；演讲者备注后续单独评估，避免把隐藏说明默认混入正文。
6. XLSX 按工作簿关系确定工作表顺序，解析 shared strings、inline strings、布尔值、错误、公式与缓存值。输出以工作表标题和显式单元格坐标组成稳定文本；空白区域不展开。首版不计算公式、不执行宏、不读取外部链接、不展开数据透视表或图表。日期/数值格式只在能确定转换时显示，否则保留原始值。
7. 结构化输出继续进入现有 `ParsedDocument → Parent/Child → FTS/vector` 管线。PPTX 的 Parent 默认是单张幻灯片；XLSX 的 Parent 默认是工作表内有界的连续行区块。字符偏移仍以最终解析文本为准，坐标或页码同时写入可见文本和定位元数据。

## 备选方案

### `python-pptx` + `openpyxl`

API 成熟、格式兼容面更广，但引入了 LoreDock 不需要的编辑与生成能力。`python-pptx` 的 Pillow、XlsxWriter 依赖增加桌面打包面；`openpyxl` 仍需额外 XML 防护。若实际样本证明受限解析器兼容性不足，可分别在适配器后替换，不改变领域或 API 契约。

### 两种格式均使用标准库 ElementTree

依赖最少，但安全配置、命名空间处理和流式能力更弱。项目已经间接携带 lxml，继续使用单一 XML 引擎的收益高于去掉这一显式依赖。

### LibreOffice 无头转换

格式覆盖广且接近办公软件渲染结果，但安装体积和进程管理成本远超轻量桌面产品，不作为默认组件。以后可作为服务器端可选增强，不能成为本地导入的必需条件。

## 影响

- 优点：PPTX/XLSX 共用容器安全、关系解析和限制逻辑；默认安装不增加 Office 应用或大型新运行时；引用可以自然映射到幻灯片和单元格。
- 代价：需要维护一组明确受限的 OOXML 读取代码；首版兼容面小于完整 Office 库。
- 风险：生产工具写出的非标准关系、错误 worksheet dimension、复杂 rich text 和扩展命名空间可能丢失文本。必须以真实跨来源样本测试，不可只使用项目自生成文件。
- 兼容性：新增格式不改变现有 API 字段和索引 schema；解析文本变化仍会通过现有原子来源重建处理。

## 验证

1. 建立由 Microsoft Office、LibreOffice、WPS 和至少一种程序库生成的非敏感 PPTX/XLSX 固定样本。
2. 覆盖幻灯片标题/正文/表格/隐藏页，以及工作表顺序、shared/inline strings、公式、日期、合并单元格、空行和 Unicode。
3. 覆盖损坏 ZIP、路径穿越、超量成员、高压缩比、DTD/实体、外部关系、宏和超大工作表；失败必须有可理解错误且不留下混合索引。
4. 对解析文本、字符范围、页码/坐标、Parent/Child 边界和删除一致性建立单元及 API 回归。
5. 在 Windows 独立 Core 中比较加入格式前后的压缩与安装体积，并执行真实桌面导入、预览、搜索和引用定位。
