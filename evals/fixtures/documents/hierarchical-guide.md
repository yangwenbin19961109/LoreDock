# 分层检索指南

## 子块召回

LoreDock 使用较小的 Child Chunk 参与 BM25 和向量排名。这样可以准确命中具体术语、配置项和事实，而不会让整篇文档的其他主题干扰分数。

Child Chunk 必须保存稳定的 source ID、字符范围和标题路径。即使索引重建，这些引用仍然可以回到原始资料的对应位置。

## 父级上下文

Parent Section 表示标题章节、页面组、表格区域、代码作用域或问答单元。Parent 本身是可重建上下文，不是新的事实来源。

命中 Child 之后，系统才按需读取 Parent 或相邻 Child。完整章节超过预算时，只返回包含命中内容的连续范围，不能默认塞入整篇文件。

## 上下文预算

当前工程初始预算是 4000 个字符，但这个数字不是正式产品参数。最终预算必须通过固定评测集比较上下文完整度、重复率、延迟和 Agent 任务成功率后确定。

同一 Parent 中多个 Child 同时命中时，结果按 context ID 分组去重，避免相同章节反复占用上下文窗口。

## 降级策略

Embedding 不可用时，BM25-only 仍然使用相同的 Parent 和相邻块扩展规则。降级只改变候选召回方式，不应破坏引用和上下文能力。

Reranker 失败时保留 RRF 融合结果，不允许整次搜索失败。
