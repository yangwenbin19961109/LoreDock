# Phase 3 桌面端 MVP 交付记录

## 第一批：知识库与资料导入

当前第一批 UI 已从静态工程欢迎页升级为调用真实 Core 的知识库管理界面：

- 启动后并行检查 Core 状态并读取知识库列表。
- 支持创建知识库并立即切换到新知识库。
- 支持在多个知识库之间切换并读取各自资料列表。
- 支持通过文件选择器批量导入 Markdown、TXT、PDF 和 DOCX。
- 展示资料名称、媒体类型、文件大小和处理状态。
- 提供首次使用空状态、Core 离线状态、操作中状态和 API 错误提示。
- 所有业务操作通过 `/api/v1` 调用 Core；UI 不直接访问 SQLite 或模型。

本批尚未实现拖放事件、搜索与引用预览、资料删除、知识库重命名/删除、任务轮询与失败重试。这些内容按 Phase 3 后续批次实现。

## 第二批：搜索与引用预览

- 支持在当前知识库执行真实 `/search` 请求，默认使用 Core 的混合检索。
- 提供“仅全文检索”开关，用于模型不可用时的 BM25-only 验收与故障排查。
- 搜索结果显示来源文件、标题路径、命中正文和页码或字符范围。
- 当 Core 返回的 Parent 上下文大于命中 Child 时，允许用户展开或收起上下文。
- 切换知识库时清理旧搜索结果，避免把不同知识库的引用混在同一页面。
- 修复应用工厂忽略 `LOREDOCK_DATA_DIR` 环境变量的问题，并增加回归测试。

本批不把融合分数显示为概率，也不在 UI 中直接读取索引数据库。来源详情预览、命中高亮和有界原文继续读取将在后续批次完善。

## 第三批：渲染图对齐、资料预览与任务状态

本批以 `assets/mockups/loredock-main-library-ui-v1.png` 为视觉基准，将页面调整为左侧导航、中间资料工作区、右侧固定详情的三栏布局：

- 左栏保留全局导航层级与“我的知识库”列表，未实现的入口保持禁用。
- 中栏搜索框、添加资料按钮和资料表格的密度、选中态与状态标签参照渲染图。
- 右栏提供预览/详情标签页，通过 Core API 读取原文，不直接访问本地文件。
- 点击资料行即可预览；点击搜索结果会选择对应来源并按精确字符范围高亮命中内容。
- 资料详情展示媒体类型、大小、索引状态、添加时间、稳定 Source ID 与当前引用。
- 空知识库支持文件选择和拖放导入。
- 导入后保留 Job 状态并轮询未完成任务；失败任务在资料行提供重试入口。

渲染图中的账号头像、收藏、XLSX/PPTX 和多人协作尚不属于当前阶段，界面没有伪造这些能力。

## 第四批：重命名与完整删除

- 页头提供知识库重命名和删除入口，右侧资料详情提供资料删除入口。
- 知识库重命名只修改用户可见元数据，不触发资料或索引重建。
- 删除前展示具体目标名称、影响范围和不可撤销提示，必须经过二次确认。
- 删除请求只携带稳定 Library ID 或 Source ID；UI 不构造路径、通配符或文件删除命令。
- 删除资料后同步清理资料列表、搜索结果、任务状态、预览和当前引用。
- 删除知识库后切换到剩余知识库；没有剩余项时回到首次使用空状态。
- API 客户端显式支持无响应体的 HTTP 204，避免成功删除后错误解析 JSON。

## 第五批：资料列表可用性与安全预览提示

- 资料列表支持按名称、媒体类型或处理状态筛选，并可按最近更新、名称或文件大小排序。
- 资料列表通过 Core 的不透明 keyset 游标按每页 10 条读取，筛选和切换排序时自动回到第一页。
- Core 支持 1～200 条的有界页大小，使用稳定 Source ID 作为同值排序的次级键；游标绑定筛选和排序条件，错误复用会返回稳定的 `invalid_cursor` 错误。
- PDF 和 DOCX 仍通过 Core 返回解析后的纯文本，不执行来源文件中的脚本或嵌入内容；预览区明确提示这是安全提取文本，且不会修改原文件。
- Core 的分页、筛选和游标错误边界已增加 HTTP 集成测试，Web API 查询参数已增加客户端测试。

## 第六批：桌面 Core 生命周期

- Tauri 启动时选择动态回环端口，并以随机、仅进程生命周期内有效的 Bearer Token 启动 Core。
- Core 配置令牌后拒绝未认证请求；Web API 适配器仅在 Tauri 环境中取得连接信息并附加令牌，普通浏览器开发仍使用相对 `/api/v1` 路径。
- Tauri 等待 `/version` 握手并校验 API v1，启动失败会保留桌面界面所需的可理解错误，不回退到不安全的固定监听。
- 关闭桌面窗口时调用受保护的 shutdown endpoint，让 Uvicorn 和 SQLite 正常收尾；五秒内未退出才强制终止所属子进程。
- Windows 开发环境已完成真实启动、动态端口、401 防护和窗口关闭后子进程退出烟雾测试。
- PyInstaller `onedir` 构建会收集 ONNX Runtime、Tokenizers 和 sqlite-vec，生成约 112.8 MiB 的独立 Core；真实二进制已通过健康检查、401、建库、Markdown 导入/索引和优雅退出测试。
- Tauri 发行配置把 Core 目录映射到 `core/` resource；发行桌面程序已确认从资源目录启动 `loredock-core.exe`，并成功生成 MSI 与 NSIS 两种 Windows 安装包。

Windows 安装包尚未完成代码签名、安装/升级/卸载矩阵和干净虚拟机验收；macOS/Linux sidecar 与生命周期也尚未构建。因此这些产物仍是本地验收包，不能描述为正式可分发版本。

## 第七批：Core 异常恢复与诊断

- Tauri 使用独立监督线程持有 Core 子进程；异常退出后按 500 ms、1 秒和 2 秒退避，最多自动重启三次。
- 正常窗口关闭走优雅 shutdown，不计入恢复预算；自动恢复耗尽后保持桌面存活并进入 `failed`，避免无限崩溃循环。
- 桌面向 Web 暴露 `starting`、`ready`、`recovering`、`failed`、`stopped` 状态、稳定错误码和重启次数；Bearer Token 只存在于单独的连接契约中。
- Web 每秒同步桌面状态；恢复成功后重新读取健康状态和知识库列表，恢复期间禁用写入操作。
- 恢复面板显示可理解错误，支持复制不含令牌的诊断摘要；失败态提供人工“重新启动 Core”入口并重置恢复预算。
- Windows Release 烟雾测试确认：强制终止 ready Core 后产生新 PID 和新动态端口；持续启动失败在三次恢复后停止派生进程；最终关闭无孤儿进程。

## 验证

- 使用临时数据目录实际创建知识库，并通过 Core 导入、解析和索引 Markdown 资料。
- 浏览器刷新后能从持久化 Core 数据恢复知识库和资料列表，资料状态显示为 `ready`。
- Web ESLint、TypeScript、Vitest 和生产构建通过。
- Tauri `--no-bundle` release 构建通过。
- Windows 独立 Core、资源化 Release 桌面程序、MSI 和 NSIS 构建通过。
