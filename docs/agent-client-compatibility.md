# Agent 客户端兼容性扩展

## 需求背景

当前“手动添加”只提供 Codex 与 Cursor 两种客户端配置。产品需要扩展为面向主流 Agent 工具的统一连接入口，避免每增加一个客户端就在界面和业务逻辑中硬编码分支。

## 产品目标

- 用户在“手动添加”中选择自己使用的 Agent 客户端，即可获得对应的配置格式、配置位置和重新加载说明。
- 客户端列表由可扩展适配器注册表提供，不在 UI 中写死 Codex/Cursor 判断。
- 始终提供“通用 MCP 客户端”选项，输出标准 stdio 启动信息及结构化参数，覆盖尚无专用适配器的工具。
- 同一份 LoreDock 连接授权和启动描述可以生成多种客户端配置，不重复创建权限或保存明文令牌。

## 功能范围

1. **客户端选择器**：展示名称、图标、平台、支持的 MCP 传输方式和验证状态；支持搜索或分类，避免客户端增加后下拉列表失控。
2. **客户端适配器**：每个适配器负责配置格式、默认配置位置、服务命名规则、转义、合并说明和重新加载说明。
3. **通用 MCP 模式**：提供可复制的命令、参数及通用 JSON 示例，不承诺未经验证客户端可以直接导入。
4. **能力与状态标签**：明确区分“官方支持 MCP”“LoreDock 已生成配置”“自动化测试通过”“真实客户端验收通过”。
5. **安全合并说明**：只添加或更新 LoreDock 对应条目，不覆盖用户已有 MCP 服务；配置不得包含 Core 管理令牌或系统凭据。
6. **兼容性矩阵**：按客户端版本、操作系统、配置作用域、传输方式和验证日期记录结果。
7. **失效与降级**：客户端格式发生变化时，专用适配器可以单独停用，并回退到通用 MCP 指引，不影响已有 LoreDock 连接。

## 实施原则

- “主流”不等于默认宣称支持。候选客户端需经过格式调研、自动解析测试和至少一次真实客户端验收后，才能标记为“已支持”。
- 客户端能力会变化，支持名单和版本范围通过数据/适配器维护，不散落在 React 组件中。
- 首版继续以复制配置和人工确认合并为主，不静默修改第三方客户端配置，也不绕过其安全限制。
- 客户端适配层只负责连接配置，不复制 MCP 检索、授权或诊断业务逻辑。

## 推荐实施顺序

1. 定义客户端适配器接口、能力字段、验证状态和兼容性矩阵格式，并记录 ADR。
2. 将现有 Codex、Cursor 配置生成迁移到适配器，保持输出兼容。
3. 增加通用 MCP 客户端适配器和可搜索客户端选择器。
4. 按使用优先级逐个增加候选客户端；每个客户端独立提交配置样例、解析测试和真实验收记录。
5. 增加格式失效检测、适配器停用和通用模式回退。

## 验收条件

- 新增客户端无需修改 Agent 连接页面的核心流程或复制一套连接业务逻辑。
- Codex 与 Cursor 现有配置保持向后兼容。
- 通用 MCP 模式能完整表达 LoreDock stdio 启动命令和参数，且不包含凭据。
- 每个标记“已支持”的客户端都有明确版本、平台、配置作用域和真实连接证据。
- 合并说明明确保留其他 MCP 服务；撤销 LoreDock 连接后，残留客户端配置不能继续访问知识库。
- 未验证或暂时失效的客户端不会显示误导性的“已连接/已支持”状态。
