## 阶段准入（2026-09-04）

### 逐连接自检：界面接入

- 已有连接下新增“检查连接”折叠区，可选授权知识库和最多 2000 字符的测试关键词；留空只做基础检查，填入后执行本地全文搜索和引用读取。
- 显式展示五个阶段的通过/无命中/失败/未检查，不把未执行项目算作通过；保留“本地自检不验证外部 Agent 或握手”的说明。关键词与结果仅保留在当前组件状态，不新增本地存储。
- 独立检查中状态防止重复提交，30 秒后中止前端等待；组件卸载取消请求并忽略晚到结果。修改输入清除旧结果，撤销连接移除区域，授权库列表改变重建组件。失败提供重试或修复提示，不回显原始异常。
- 新增 API 边界校验与 10 项单元测试；浏览器回归覆盖明暗主题、两种视口、基础通过、无命中、凭据失败、网络失败后可重试及撤销清空；代表性截图无横向溢出。未更改 Core/MCP 契约或数据格式。
- 下一步桌面人工验收：基础自检、包含命中的关键词查询、空结果、失败恢复，以及 P4-A01 与手动配置流程。Cursor 实机验收仍暂缓；本轮浏览器使用模拟 API，不代替真实端到端验收。

### 逐连接自检：Core 接口

- 新增 owner-only `POST /api/v1/agent-connections/{id}/diagnostics`。空对象执行凭据、启动配置生成和授权库列表检查；同时提供 `library_id/query` 时再执行一次最多 1 条的 BM25-only 查询和命中引用读取，不调用模型。
- 响应含 `scope=local_core`、`status`（passed/no_matches/failed）、`stage`、`code`、`completed`、`hit_count` 与固定 false 的 `external_agent_verified`。无命中不是连接失败；未执行的检索/读取不会出现在 completed 中。
- 每次资料读取前重新解析凭据授权，不持久保存自检结果。正常响应 no-store，不返回查询、正文、文件名、路径、令牌或原始异常。输入沿用严格校验，query 最多 2000 字符且必须与 library_id 成对提供。
- 此接口直接复用 Core MCP 服务层，未启动 bridge 子进程，也未验证系统凭据在外部进程中的访问能力或实际 socket/stdio 握手；setup 阶段只检查能否生成启动配置。不能将本地检查通过显示成“Agent 已连接”。
- 新增 6 项测试，Core 全套 89 项通过、1 项系统测试默认跳过；Pyright、修改文件 Ruff/格式检查通过，仍有一条 Starlette/httpx 弃用警告。本轮没有 UI 或检索策略变更，无数据迁移。
- 下一步：接入逐连接自检按钮、可选测试查询与阶段结果 UI，明确显示未检查的外部客户端环节；Cursor 实机验收继续暂缓。

项目负责人同意先进入 Phase 4。Phase 3 功能与布局人工验收已通过，Windows 干净虚拟机安装、升级、卸载和数据保留矩阵调整为发布前必验项，未执行、未视为通过。搜索排序调优仍后置到真实 Agent/MCP 接入之后。

## 第一批：只读契约与授权服务基座

- 增加 `loredock.mcp`，复用 HTTP 使用的 `LoreDockService`，不访问数据库或模型运行时，不新增网络监听器。
- 实现 `list_libraries`、`search_knowledge`、`read_source` 的类型化请求和结果；目前是内部服务层，契约仍为草案，并非已可连接的 MCP Server。
- 默认授权集合为空；可信调用层注入允许的知识库 ID，工具参数不能扩大授权。读取必须再次检查来源确实属于请求中的已授权知识库。
- 搜索暂支持单知识库，最多 10 条，每条文本最多 1600 字符；保留原始排序和完整命中结束偏移，截断片段有独立结束偏移和标志。结果含来源名、稳定 ID、页码、标题路径和后续读取参数。
- 原文读取默认 4000、最多 8000 字符，通过额外探测一个字符返回准确的 `next_start`；知识库列表默认 20、最多 50 条，按稳定 ID 分页。
- 不返回存储路径或原始异常字段；资料内容始终作为不可信数据处理，正文中用户原有的路径文字不会被自动改写。
- 当前授权集合只是服务层边界，不是认证或持久授权系统。后续 HTTP/stdio 入口必须从可信凭据解析实时授权，并处理撤销，不能直接信任客户端传入集合。

验证：新增 3 项离线集成/契约测试，覆盖默认拒绝、知识库过滤、越权搜索、跨库来源读取拒绝、引用往返、读取分页、列表分页和参数上限；使用临时资料与确定性模型，不调用外部模型。

## 第三批：专用只读凭据与受保护入口

- 新增桌面 owner 专用的 `POST /api/v1/agent-grants` 和 `DELETE /api/v1/agent-grants/{id}`；没有配置桌面鉴权时不能签发凭据。
- 随机只读令牌单次返回，内存中仅保存摘要和知识库授权集合；Core 重启后失效，不写入配置文件或数据库。当前没有凭据管理 UI、系统钥匙串、自动续期或持久授权。
- `POST /api/v1/agent-tools/call` 始终校验专用令牌，拒绝桌面令牌替代；只读令牌不能访问原有管理 API。工具执行仍经过六工具白名单和逐库授权。
- 请求体最多 32 KiB；同步 Core 调用在线程池执行，不阻塞异步事件循环。
- 撤销后续请求立即失效；已授权并开始执行的请求不被中途取消。详见 [ADR 0010](decisions/0010-agent-read-credentials.md)。
- 新增 4 项鉴权测试，Core 全量 54 项测试通过；现有 HTTP 契约保持兼容，无数据库迁移、无排序修改。

下一步：接官方 MCP SDK 与 stdio bridge，消费这个受保护入口，添加协议握手、工具发现、调用及错误映射测试。此 HTTP 入口仅用于 bridge，不代表 MCP 已可连接；本轮没有修改用户 Agent 配置或签发实际用户凭据。

## 第四批：官方 SDK 与 stdio bridge

- 接入官方 MCP SDK 1.29.1（约束 `<2`），增加 `loredock-mcp` 和 `python -m loredock.mcp.bridge` 开发入口。
- 六个只读工具使用既有参数 Schema，声明只读提示；结果同时返回文本和结构化数据，错误采用 MCP `isError` 和稳定错误码。
- Bridge 只接受带明确端口的数字回环 HTTP 地址，禁用代理和重定向，设置 30 秒超时与 512 KiB 响应上限，不访问知识库磁盘或启动 Core。
- 开发环境通过 `LOREDOCK_BRIDGE_URL` 与 `LOREDOCK_BRIDGE_TOKEN` 注入连接参数。必须使用只读凭据，不得使用桌面管理令牌，不得将真实令牌提交或嵌入文档。
- 新增 8 个测试用例：URL 安全边界、独立 stdio 子进程握手/发现、SDK 协议到真实 Core 的搜索/读取/撤销、重定向拒绝。协议到 Core 的测试使用进程内 ASGI，不声称已完成真实 Agent 或安装包联调。
- 依赖与打包影响见 [ADR 0011](decisions/0011-local-mcp-stdio-bridge.md)。没有数据库迁移或排序策略修改。

下一步：实现凭据管理与连接向导（含 Core 重启后的恢复提示），随后进行 Codex/Cursor 真实客户端验收。持久授权、系统钥匙串、独立 bridge 打包及跨平台验证尚未完成。当前仅开发入口可运行，不代表普通用户已能一键接入。

### 第五批新增：Core 与稳定 bridge 接入

- 桌面鉴权启用时打开独立 `agent-connections.sqlite`；新增 owner 专用创建、列表、撤销 API `/api/v1/agent-connections`。创建只返回元数据与 ID，不返回令牌；工具鉴权支持持久连接，旧临时授权接口保持兼容。
- 系统凭据后端延迟到实际保存/读取时访问，不在 Core 启动时读取用户密码。撤销结果区分“访问已撤销”和“系统凭据清理是否成功”。
- Core 在 profile 下原子写入不含秘密的 `agent-endpoint.json`，记录回环 URL 与实例 ID；退出时清理所属记录。每个 profile 只允许一个 Core 实例。
- 新增开发启动参数：`python -m loredock.mcp.bridge --profile <绝对数据目录> --connection <连接ID>`。旧 URL/token 环境参数模式继续可用。
- 稳定模式每次工具调用在线程中重新解析地址并从系统凭据库读取令牌，bridge 不打开 SQLite，不自动启动第二个 Core，也不把令牌写入配置或 stdout。
- 新增两项测试覆盖 Core 重启后的持久授权恢复、端口变化、只读令牌不能管理连接、撤销后旧令牌拒绝，以及外部发现地址拒绝与旧实例退出保护。

### 第五批新增：复制给 Agent 界面

- 启用左侧“Agent 连接”入口，沿用现有组件与主题，以独立工作区提供知识库选择、命名、创建连接、重新查看说明和两步撤销，不遮挡知识库主界面。
- 新增 owner 专用 `GET /api/v1/agent-connections/{id}/setup`。说明包含当前开发 Python 启动命令、绝对 profile 路径与稳定连接 ID，不读取或返回令牌。提示 Agent 合并而非覆盖配置，并通过握手和 `list_libraries` 确认接入，不自动修改外部 Agent 配置。
