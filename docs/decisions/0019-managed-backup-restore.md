# ADR 0019：一致性托管备份与重启边界恢复

- 状态：Accepted
- 日期：2026-09-09

## 背景

LoreDock 的用户数据同时包含 `app.sqlite`、每个知识库的原始资料、解析产物、索引和构建清单。直接复制活跃 SQLite 主文件可能遗漏 WAL 内容；在运行中的 Core 内替换数据库则可能让后台任务、连接和文件句柄观察到混合状态。

## 决策

一期提供由 Core 管理的本机备份：

1. `app.sqlite` 与每个 `index.sqlite` 都通过 SQLite Backup API 生成一致性副本。
2. 原始资料、解析产物和 manifest 与数据库副本一起写入版本化归档；归档逐文件保存大小和 SHA-256。
3. 创建完成后原子提交归档。列出、显式校验和恢复前校验使用相同的路径、展开量、清单、哈希、SQLite `quick_check` 和外键检查。
4. 恢复请求只写入待恢复标记，不在运行中替换数据。桌面端随后重启 Core，在任何数据库连接建立之前完成目录切换。
5. 安排恢复前自动创建当前状态的恢复点。切换失败时回滚原数据库、WAL/SHM 和知识库目录；成功后才删除待恢复标记。
6. 备份保存在 LoreDock 数据目录的 `backups/` 下，不包含系统凭据或模型缓存。首批不支持导入任意外部归档或自动清理历史备份。

## 影响

- 恢复会将知识库整体回到备份时状态，不与当前数据合并。
- 恢复依赖一次 Core 重启；浏览器服务器模式需由运维方完成重启。
- 索引包含在首批归档中，可在恢复后立即搜索；它仍是可重建数据，恢复校验不会改变原始资料的事实来源地位。
- 后续增加外部归档导入、加密、保留策略或跨版本迁移时，需要扩展备份格式版本和攻击性测试。
