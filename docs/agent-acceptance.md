## 自动配置失败时的手动兜底

在“复制给 Agent”下展开“Agent 没能自动配置？手动添加”，选择客户端并复制配置。先备份文件；Codex 合并独立配置段，Cursor 合并 `mcpServers` 内条目，已有同名条目应更新而非重复添加。不要覆盖原文件或关闭安全限制。保存后重新加载服务或客户端，再发起新会话，调用知识库列表、搜索及引用读取验证。

配置由 Core 从同一个启动描述生成，不从自然语言说明中提取；包含本机路径和连接 ID，不包含凭据。仅用于同机同用户；LoreDock 需保持运行。撤销连接后也应移除客户端条目。旧版 Core 未返回 `configurations` 时，仍显示原连接说明，并提示更新后再使用手动配置。

格式与位置依据 [OpenAI 官方 MCP 文档](https://learn.chatgpt.com/docs/extend/mcp?surface=cli) 和 [Cursor 官方 MCP 文档](https://cursor.com/docs/mcp)：Codex 使用用户目录或受信任项目的 `.codex/config.toml`；Cursor 使用用户目录或项目的 `.cursor/mcp.json`。本轮未写入用户配置，也未进行客户端真实调用；Cursor 实机验收按用户决定暂缓。

## 非技术用户操作流程

1. 在 LoreDock 新建一个专用于验收的知识库，导入不含个人信息的文本。
2. 创建只读连接，只勾选该测试知识库。
3. 点击“复制连接说明”，粘贴到目标 Agent，并批准需要的配置变更。
4. 保留原有 MCP 服务，不覆盖整个配置文件；不要提供管理令牌或读取系统凭据内容。
5. 必要时按客户端要求重新加载 MCP 或重开会话，观察真实工具调用记录。

建议测试文本：`moonstone 的保留期为 17 天。到期后由资料管理员确认归档。`
