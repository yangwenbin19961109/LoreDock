# Phase 3 检索排序诊断

诊断日期：2026-09-03

状态：保留为后续质量优化基线。项目负责人决定在 Phase 4 完成 Agent/MCP 真实接入、能够观察代表性实际查询之后再评判排序效果；当前不调整生产检索权重、分块、模型或 reranker，也不以此阻塞 Phase 3 验收。

## 结论

当前搜索结果会按后端返回的最终分数降序展示，前端没有再次排序，因此“期望内容排在第三位”不是 UI 顺序错误。100 条固定评测显示：向量检索有效，但仅向量的首位质量低于 BM25；等权 RRF 混合提高了召回与跨语言能力，却没有提高当前数据集的整体 Top-1。现阶段不能简单归因于“向量化不好”，更准确的原因组合是：

1. 多份资料或多个 Child 包含相近事实，候选之间存在竞争。
2. E5 更擅长语义和跨语言召回，但对精确词项查询未必优于 BM25。
3. 当前等权 RRF 只使用两个通道的排名，不理解哪一段真正完整回答了问题。
4. 当前没有生产 reranker 对融合后的少量候选进行二次语义判断。

## 同集对照

语料为 14 份资料、43 个 Child，问题为 100 条，结果上限为 10，Parent 上下文策略保持一致。

| 模式 | Recall@10 | Top-1 | MRR | 引用正确率 | 期望片段覆盖 |
| --- | ---: | ---: | ---: | ---: | ---: |
| BM25-only | 0.975 | 0.770 | 0.867 | 1.000 | 0.990 |
| E5 vector-only | 0.982 | 0.710 | 0.832 | 1.000 | 0.990 |
| BM25 + E5 + 等权 RRF | 0.982 | 0.760 | 0.867 | 1.000 | 0.990 |

两条跨语言问题的结果更能体现向量通道价值：BM25 Top-1 为 0/2、MRR 为 0.25；vector-only Top-1 为 1/2、MRR 为 0.75；混合检索 Top-1 为 1/2、MRR 为 0.62。因此不能为了少数精确词项查询直接关闭向量检索。

## 分数解释

UI 当前展示的是最终排名相关度。混合模式下它是 RRF 融合分数，BM25-only 下是单通道的排名分数；它们都不是余弦相似度、准确率或概率，只适合解释同一次查询中的相对顺序。评测输出现已记录每条查询、返回来源和逐项分数，便于复现具体排序问题。

## 真实 Agent/MCP 接入后的优化顺序

1. 将用户实际出现问题的查询、期望来源和期望片段加入可再分发的固定评测；私人资料不得进入仓库。
2. 将评测扩充到 200～500 条，重点增加多个文档共享关键词、跨 Child 答案、代码和中英跨语言问题。
3. 在扩展集上实验词法/向量加权 RRF，只有 Recall、Top-1/MRR、跨语言子集和延迟共同可接受时才调整默认权重。
4. 评估轻量本地 reranker，对 Top 10～20 融合候选二次排序；失败时必须回退到原融合顺序。
5. 在 UI 中继续使用“相关度”，不把分数显示为百分比概率。

本轮只增加离线 vector-only 诊断模式和逐题分数记录，没有修改生产搜索默认参数。
