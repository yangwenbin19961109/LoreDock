# ADR 0016：受限且固定解析地址的 URL 快照

- 状态：Accepted
- 日期：2026-09-07
- 决策负责人：LoreDock 项目负责人
- 替代：无

## 背景

Phase 5 需要让普通用户通过网址导入公开网页，同时遵守本地优先、原始来源可追踪和 URL 摄取必须防范 SSRF 的产品约束。直接让通用 HTTP 客户端跟随重定向，会允许目标域名解析到回环、私网、链路本地或云元数据地址；仅在请求前检查域名也无法防止连接时发生 DNS rebinding。

## 决策

1. Core 提供独立的 URL 导入用例和 HTTP 端点；UI 只提交网址，不直接从 WebView 请求目标站点。
2. 仅接受绝对 `http`/`https` URL、标准 80/443 端口且不允许 URL 内嵌认证信息。
3. 每一跳先解析域名，并要求所有返回地址均为公网地址；随后把 TCP 连接固定到其中一个已验证地址。HTTPS 仍使用原域名完成 SNI 和证书校验。
   - 若系统解析结果全部位于代理常用的 `198.18.0.0/15` Fake-IP 网段，且用户输入的是域名而非 IP，Core 通过固定 `1.1.1.1`、验证 `cloudflare-dns.com` TLS 证书的 DNS-over-HTTPS 查询获得真实 A/AAAA 地址，再执行相同的公网校验。该兜底会向 Cloudflare 解析器披露所导入网址的域名。
   - 直接输入 Fake-IP、回环、私网、链路本地或其他保留地址不会触发兜底，始终拒绝。
4. 最多跟随三次重定向，每一跳重新执行完整 URL、DNS 和地址校验；拒绝 HTTPS 降级到 HTTP。
5. 请求不使用系统代理，声明只接受 identity 编码；拒绝压缩响应、非 HTML/纯文本媒体类型、非 200 结果和超过 10 MiB 的响应。
6. 按响应声明字符集解码后统一保存为 UTF-8 快照，再进入现有 HTML/TXT 安全解析、内容哈希去重、分块和索引链路。脚本、样式与嵌入内容仍不进入索引。
7. 元数据库新增 `source_kind` 与 `origin_url`；旧来源迁移为 `file`，URL 来源记录最终规范化地址。数据库 schema 从 v5 升级到 v6，迁移可重试且不修改已有来源内容或索引。
8. 当前快照是一次性导入，不登录网站、不处理 Cookie、不执行 JavaScript、不下载附件或外链图片，也不持续同步页面。

## 影响

- 用户能够以与本地文件一致的方式搜索和引用公开网页快照。
- JavaScript 渲染站点、需要登录的页面、非标准端口和压缩响应当前不支持；这是首版明确的安全与轻量边界。
- 相同内容哈希仍按知识库去重，首次保存的来源元数据保持不变。
- 后续刷新、内容变化检测和快照历史可以复用 `origin_url`，但必须作为独立用例设计，不能静默覆盖用户现有快照。

## 验证

1. 单元测试覆盖协议、认证信息、端口、公网/私网/混合 DNS、Fake-IP 安全兜底、IP 字面量、重定向复验、HTTPS 降级、压缩、媒体类型、字符集和大小限制。
2. 集成测试使用注入式确定性传输，不访问互联网，覆盖快照保存、HTML 主动内容排除、搜索、引用和 v5→v6 迁移。
3. HTTP 与 Web UI 回归覆盖端点契约、来源 URL 展示、失败提示和导入完成后的资料刷新。
4. 桌面人工验收使用非敏感公开网页；不以本机或内网服务绕过 SSRF 保护。
