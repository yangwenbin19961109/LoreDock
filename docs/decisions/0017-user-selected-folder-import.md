# ADR 0017：用户主动选择的有界文件夹导入

- 状态：已接受
- 日期：2026-09-07

## 背景

Phase 5 需要支持文件夹递归导入，但当前批次不包含长期文件监听。桌面 UI 已能通过受保护的 HTTP 上传接口导入单个或多个文件。若为了本批功能直接赋予 Core 任意目录读取权限，会扩大文件系统边界，并把后续监听所需的持久授权提前混入当前交付。

## 决策

首版文件夹递归导入使用桌面 WebView 的目录选择能力。只有用户明确选择的文件会作为浏览器 `File` 对象进入 UI；UI 先完成有界预检，用户再次确认后，才按顺序复用现有单文件上传和索引接口。

预检边界如下：

- 只接收当前已支持的后缀。
- 单文件继续受 Core 的 100 MiB 上限约束。
- 单次最多导入 500 份受支持资料。
- 单次可导入文件总体积最多 1 GiB。
- 不支持格式和超大文件明确列为跳过，不发往 Core。
- 单项失败不回滚已经成功的资料；保留失败项以便重试。
- 停止操作中止客户端等待并阻止后续文件开始上传；服务端已经接收的当前文件可能完成，重试依靠内容哈希安全去重。

相对路径只用于本次预检和进度展示，不写入当前公开来源契约。Core 仍对上传文件名进行取 basename 处理，不能利用文件夹层级逃逸资料根目录。

## 结果

- 本批无需新增数据库迁移、Core 文件系统权限或 Tauri 文件系统插件。
- Web 版本与桌面 WebView 可复用相同的用户选择流程。
- 文件夹层级不会成为资料身份；同内容文件继续按现有内容哈希去重。
- 浏览器中止上传不能保证取消已经进入 Core 的同步解析任务，界面必须使用“停止后续导入”语义，并在结束后刷新资料列表。
- 长期增量监听已调整为第二期功能；届时需要在 Tauri 层设计可撤销的目录授权、重启恢复、变化防抖和路径安全，不能把本 ADR 的临时 `File` 对象当作持久目录句柄。

## 被否决的方案

### 让 Core 接收任意本地绝对路径

这会扩大 HTTP API 的文件读取能力，增加路径穿越和越权读取风险，也不适用于远程 Web 部署。

### 本批直接实现长期目录监听

监听涉及持久授权、平台差异、重启恢复、删除判定和原子更新，不能与一次性递归导入在同一批次中隐式交付。

### 将整个文件夹打包为 ZIP 上传

会增加压缩包展开、Zip Bomb、临时空间和失败恢复复杂度，也无法复用现有逐资料进度与内容去重。
