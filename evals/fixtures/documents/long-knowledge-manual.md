# LoreDock 长文配置与运维手册

本资料用于验证长文档中的精确事实检索、父子分块和上下文扩展。各项参数均为评测夹具，不自动构成正式产品默认值。

**资料名称**

知识库显示名称最多 120 个 Unicode 字符；超出长度时保存操作应返回字段校验错误，不应静默截断。

**单文件大小**

桌面端单个本地资料的默认导入上限是 100 MiB。服务器管理员可以降低限制，但不能绕过解压安全检查。

**原文读取窗口**

通过来源 ID 继续读取原文时，单次默认返回 8000 个字符，并返回下一段所需的稳定偏移量。

**任务重试**

可恢复的解析或索引任务最多自动重试 3 次，之后进入 failed 状态并保留诊断信息。

**融合常数**

混合检索使用 Reciprocal Rank Fusion，评测基线的 RRF 常数 K 设为 60。

**候选池**

词法检索与向量检索默认各取前 50 个 Child 候选，再进行融合、过滤和去重。

**最终结果数**

普通搜索请求默认返回 8 个上下文结果；调用方可以在安全上限内减少数量。

**Child 分块**

文本 Child 的评测目标大小是 512 个字符，硬上限为 768 个字符，相邻 Child 重叠 64 个字符。

**E5 向量**

multilingual-e5-small 生成 384 维向量，默认批量大小为 16，模型输入硬上限为 512 tokens。

**开发端口**

仅开发模式使用固定端口 49321。打包桌面应用必须使用动态端口和每进程认证秘密。

**HTTP 版本**

首个稳定 HTTP 路径前缀是 `/api/v1`；新增字段应保持旧客户端可以忽略。

**元数据数据库**

用户可见元数据存储在 `app.sqlite`，每个知识库的可重建搜索索引与它分开保存。

**索引清单**

父子混合索引的 build contract 版本是 3，清单必须同时记录 chunker、模型、维度和归一化规则。

**应用结构版本**

当前评测夹具假定应用元数据 schema version 为 2；迁移必须可重试且具有确定性。

**内容去重**

导入去重使用原始字节的 SHA-256 内容哈希，不能只比较文件名或修改时间。

**原子替换**

单个来源重建时先在旁路完成全部新 Parent 与 Child，校验成功后在一个事务中切换可见版本。

**稳定引用**

引用至少包含 library ID、source ID、chunk ID、字符起止位置；PDF 还应尽可能附带页码。

**表格单元**

表格优先把标题、表头与相关行放进同一 Parent，上下文预算不足时按连续行裁剪。

**代码作用域**

代码资料优先以类或函数作为 Parent，不应把函数签名与函数体拆到互不相关的上下文中。

**Reranker 降级**

Reranker 超时、模型缺失或输出无效时，搜索必须返回已经去重的 RRF 融合顺序。

**本地监听**

Core 的默认监听地址是 `127.0.0.1`。只有显式启用远程模式并配置认证后才允许其他接口。

**MCP 响应边界**

MCP 搜索结果必须有数量和字符预算；需要更多正文时，Agent 应使用 source ID 发起后续只读请求。

**一致性备份**

运行中的 `app.sqlite` 必须通过 SQLite backup API 或 WAL 一致性快照备份，不能只复制主文件。

**URL 导入**

URL 抓取必须拒绝回环、链路本地、云元数据和私有网络目标，并在每次重定向后重新检查目标。

**完整删除**

删除来源要清理原始副本、解析产物、FTS 行、向量、Parent、Child 和缓存，并记录精确 source ID 以便重试。
