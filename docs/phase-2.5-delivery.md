# Phase 2.5 分层上下文检索交付记录

## 已实现

- 将可重建索引 build contract 从 version 2 升级为 version 3。
- 新增 Parent Section 表，以及 Child 的 `parent_id`、`ordinal`、`previous_id` 和 `next_id`。
- Markdown 标题边界不会被普通 Child 跨越；无标题短文档仍可作为扁平资料使用。
- FTS5 与向量继续只对 Child 排名，RRF 后按 `context_id` 分组去重。
- 完整 Parent 未超预算时返回 Parent；超预算时返回包含命中 Child 的连续有界范围。
- BM25-only 与混合检索共用同一上下文扩展逻辑。
- HTTP 与 TypeScript 契约新增 matched/context 字段，原 Phase 2 字段语义不变。
- 检索评测新增 context precision、平均上下文字符数和重复上下文率。
- 检索评测新增 Child-only、相邻 Child 和 Parent 三种可重复的上下文策略，并报告期望片段覆盖率。
- v2 或未知派生索引在首次使用时旁路重建，成功后原子替换；原始资料、Source ID 和用户元数据不变。

## 当前回归基线

第二批扩展评测包含 14 份资料、100 条人工编写问题和 43 个结构化 Child，覆盖普通说明、长篇分层文档、FAQ、Markdown 表格、Python 代码、真实可解析 PDF/DOCX、运维恢复、安全边界及中英跨语言查询：

| 模式 / 上下文 | Recall@10 | 首条正确率 | MRR | 引用正确率 | 期望片段覆盖 | Context Precision | 平均上下文字符 | 重复率 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| E5 + Child-only | 0.982 | 0.760 | 0.866 | 1.000 | 0.990 | 0.106 | 369.1 | 0.000 |
| E5 + 相邻 Child | 0.982 | 0.760 | 0.867 | 1.000 | 0.990 | 0.104 | 396.4 | 0.000 |
| E5 + Parent | 0.982 | 0.760 | 0.867 | 1.000 | 0.990 | 0.104 | 396.4 | 0.000 |
| BM25-only + Parent | 0.975 | 0.770 | 0.867 | 1.000 | 0.990 | 0.108 | 375.4 | 0.000 |

Context Precision 当前以返回结果的上下文是否覆盖该题期望资料与片段计算，并以全部 Top 10 为分母，因此会随语料数量和 `result_limit` 明显变化。它用于同版本对照，不应脱离评测配置解释为概率。

本批数据上，相邻 Child 与 Parent 比 Child-only 平均多返回约 7.4% 字符，但没有提高 0.990 的期望片段覆盖率；因此不能据此继续放大默认上下文。当前仍保留 Parent 作为产品默认策略和可回退的 Child-only/相邻策略，下一批需专门加入“命中句与回答所需前提位于不同 Child”的问题，才能决定何时条件化扩展。

## 尚未满足的阶段验收项

真实本地 Embedding 已完成 12 条问题的 Pilot 接入和评测，但尚未满足以下定型条件：

1. 将当前 100 条第二批评测继续扩充到 200～500 条，并增加跨 Child 上下文依赖、更多真实 PDF/DOCX 和更大规模长文档。
2. 在扩充后的同一评测集上比较 E5、BM25-only 与哈希管线，避免小样本误判。
3. 在 1 万及以上分块重新测量真实 E5 与上下文扩展 P95、冷启动、峰值内存和索引体积。
4. 根据固定评测集确定上下文预算，而不是直接把当前 4000 字符实现值当成最终产品默认值。
5. 在 Phase 3 UI 中验证命中高亮和上下文展开，在 Phase 4 MCP 中验证有界后续读取。
