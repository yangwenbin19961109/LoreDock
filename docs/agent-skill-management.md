# Agent Skill 管理功能规划

> 产品排期：第二期功能，不属于当前一期 Phase 0～7 的开发和发布范围。本期仅保留需求记录。

## 目标

在 LoreDock 中增加面向普通用户的“Agent Skill”管理界面，用于统一查看、导入、启用、停用和分配 Codex、Cursor 等 Agent 工具使用的 Skill。该功能不改变知识库的事实来源，也不把 Skill 当作 MCP 知识检索工具。

## 产品边界

- 知识库/MCP 负责提供只读、可引用的资料；Skill 负责告诉 Agent 如何完成某类任务或调用特定工具。
- 首版管理本地 Skill，不建设在线市场，不自动下载或执行来源不明的代码。
- 不承诺所有 Agent 使用同一种 Skill 格式；通过 Agent 适配器转换或生成各工具支持的配置。
- 导入、安装或更新前必须展示来源、版本、文件清单、权限需求和风险提示。
- Skill 内容、附带脚本和外部指令均视为不可信输入；不得因导入而自动获得文件、网络、凭据或命令执行权限。

## 首版 UI 功能点

1. **Skill 列表**：展示名称、说明、版本、来源、启用状态、兼容 Agent 和最近更新时间。
2. **详情预览**：安全展示说明文件、入口、依赖、权限声明及包含的脚本/资源，不执行内容。
3. **本地导入**：从文件夹或受支持的打包文件导入，先校验结构、大小、路径和清单，再让用户确认。
4. **启用与停用**：支持全局停用，以及按 Agent 启用；停用不删除本地 Skill。
5. **Agent 分配**：选择 Skill 可供哪些已配置 Agent 使用，并显示实际同步状态。
6. **配置生成**：为不同 Agent 生成可复制的安装说明或配置片段；默认不自动修改第三方程序配置。
7. **更新与移除**：更新前展示版本差异和权限变化；移除需要确认，并且不得删除 Skill 目录之外的文件。
8. **诊断状态**：区分“已导入”“已启用”“配置已生成”“Agent 已识别”和“运行验证通过”，避免误导用户。

## 建议数据模型

- `skills`：稳定 ID、名称、版本、来源、内容哈希、清单版本、安装状态和创建/更新时间。
- `skill_agent_bindings`：Skill、Agent 类型、连接/配置目标、启用状态和最后同步结果。
- `skill_permissions`：声明的文件、网络、命令、凭据和外部工具需求。
- `skill_install_events`：导入、更新、启停、配置生成与移除的脱敏审计记录。

Skill 原始包是事实来源；解析清单、兼容性结果和生成配置均可重建。用户修改过的本地 Skill 不得在更新时静默覆盖。

## 第二期推荐实施顺序

1. 调研并固化 Codex、Cursor 的 Skill/规则扩展格式与兼容矩阵。
2. 定义 LoreDock 内部中立清单、版本规则、权限模型和 Agent 适配器接口，并记录 ADR。
3. 实现只读扫描、列表和安全详情预览。
4. 实现本地导入、校验、启停和移除事务。
5. 实现按 Agent 分配与可复制配置说明。
6. 增加更新差异、权限变化确认、诊断与跨平台测试。

## 验收条件

- 非技术用户可以在界面中完成导入、查看、启停、分配和移除，无需手工编辑配置文件。
- 未启用的 Skill 不会出现在生成给 Agent 的配置中。
- 导入包无法通过路径穿越覆盖 Skill 根目录之外的文件。
- 权限扩大、来源变化或内容哈希变化必须显式提示，不能静默更新。
- Windows、macOS 和 Linux 使用同一领域模型，平台路径与配置写入由适配器处理。
- Skill 管理失败不影响知识库检索、BM25 降级或现有 MCP 连接。

## 排期位置

该功能归入第二期产品范围，不纳入当前一期 Phase 0～7，也不作为一期发布前置条件。本期不开展格式调研、ADR、数据结构、接口、UI、Agent 适配或测试实现；进入第二期后再根据届时的 Codex、Cursor 等工具能力重新确认方案。
